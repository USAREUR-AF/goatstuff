goatstuff

Tools that show what a goat data fabric is doing, and demos that teach it.

The inspection surfaces, demos and example applications that run beside goatcore. They draw the fabric live, find routers that disagree, grade one topic, let a newcomer publish a message and watch it arrive, and stand in for sensors with synthetic publishers. None of them is needed to run a goatnet.

What it is

goat is a mesh and a Zenoh data fabric for systems that publish and subscribe. goatcore holds the mesh, the fabric, identity, the build tool and the operator CLI. goatstuff holds what you look at and play with on top of it. A surface that deploys has an Ansible role and a playbook under ops/ansible/.

Surfaces that watch the fabric

panoscope draws the whole goatnet, goat-topology draws its routers, flashlight follows one slice, stethoscope grades one target, netvis draws the mesh policy. Rust services in crates/ and ops/, web pages without a build step.

Demos that teach it

A browser playground for publish and subscribe, a zero-trust identity sandbox, an interactive deck on how systems move data, a map, and the gym: lanes of modules, each with a drill. Under ops/serve/ and ops/gym/.

Publishers that feed and test it

Synthetic vendors stand in for sensors, health publishers fill the health surfaces, trashgoat sends unusual traffic on purpose, and transform-shim converts messages between formats. Under ops/zenoh-trial-peers/, ops/goat-trashgoat/ and ops/zenoh-shims/.

Every surface, with what it shows

The status on each card is the one docs/RELEASE-CONTENTS.md gives it. Tested in CI: a workflow builds it and runs its tests on each pull request. Built: a workflow checks that it compiles or parses. Not run: no workflow here runs it.

Tested in CI

panoscope

The whole goatnet at a glance: peers as nodes, topic flows as moving edges, and the decoded stream of any topic beside them. It is the only surface that queries the fabric on request.

goat-topology

Every router, the links between them and the region each link belongs to, with findings: configurations that do not do what they appear to, routers that have gone quiet, routers that disagree with each other. It runs against stock zenohd with the REST plugin.

Name a slice of the fabric in the URL, a key, an org or a role, and watch only that slice: the server narrows its subscription to match. The status is for its analytics crate.

Trust sandbox

A local zero-trust identity playground. x509 certificates, SPIFFE workload identity, Ory sign-in and Zenoh ACLs run for real, and NetBird admission is represented; knock one layer out and the page shows which property breaks. docker compose up, then localhost:8100.

dataflows

A ten-slide interactive deck on four ways systems move data: internal only, point-to-point interface documents, request and response APIs, and publish and subscribe. Each pattern slide is a small simulation with its own controls.

The training surface: a lane of modules for each role. A module points at the document that explains its subject and adds a drill to run and the quirks that cost people time. python3 ops/gym/generate.py renders it.

A fabric peer that subscribes in one format and republishes in another with goat-transformers. Not deployed; every switch defaults to off.

Publishers put data on the fabric, surfaces read it

Most surfaces only subscribe. goat-topology's page reads what its publishers already put on the bus, so opening it, or refreshing it every second, sends nothing to any router. panoscope is the one surface that queries the fabric when someone asks. Three pieces move data both ways: transform-shim and goat-map republish what they subscribe to, and panoscope's queries get replies.

The playground runs on one laptop

The browser playground is two pieces: the static page in ops/serve/zenoh-sandbox/app/ and a local Zenoh router with the remote API WebSocket plugin. prep.sh fetches the router for your machine once; after that serve.sh needs no internet and no Docker. Click Connect, start the pretend sensor, listen on demo/**.

cd ops/serve/zenoh-sandbox/local
./prep.sh      # once, needs internet
./serve.sh     # page on :8080, router on ws://localhost:10000

Quick start

Clone the repository, then pick one.

git clone https://github.com/USAREUR-AF/goatstuff
cd goatstuff

The playground

cd ops/serve/zenoh-sandbox/local
./prep.sh && ./serve.sh

Python 3 and one download of the router. Then open http://localhost:8080.

panoscope with synthetic peers

cd ops/panoscope
./demo.sh up

Docker. Then open http://127.0.0.1:8080. The first build compiles panoscope and the data generator and takes 15 to 20 minutes; later starts take seconds. README-local-demo.md

Every Rust surface

cd crates
cargo build --release
cargo test --workspace

Rust. crates/Cargo.toml fetches panoscope-core from goatcore by tag.
