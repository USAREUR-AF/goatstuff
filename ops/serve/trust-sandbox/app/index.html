A name tells you where — not whether to trust

private mesh DNS · burn & respawn

A name tells you where to go — not whether to trust what's there. Every connection re-checks identity for itself, so sensor-gw.trust.local only has to point to an address.

  • The name never vouches for the endpoint — even a correct address just points you somewhere; the service there still has to prove who it is on connect. (The lookup isn't tamperable either: inside the private mesh it rides the encrypted, authenticated tunnel. The only DNS that lives outside the mesh is the one-time network enrollment, and that adds DNSSEC on top of the other checks.)
  • The payoff — tear a service down and stand a fresh one up under the same name any time; nobody changes the address they use, because the new one re-proves its own identity.

Try it in order:

  1. A name gives you an address — and nothing more.
  2. New service, new credential, same name — watch it still work, because the new one re-proved itself.
  3. Same name, same address — but no valid identity. Watch the connection get refused; the name didn't help it.

The takeaway: the name is just an address. Trust comes from identity, re-checked every time — which is exactly why a service can be swapped, patched, or moved in seconds without anyone ever trusting the wrong thing.
